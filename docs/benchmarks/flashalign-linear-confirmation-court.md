# Flashalign automatic linear confirmation court

This note records the pre-execution seal for FA-L30. The Flashalign candidate
has not been run on these fixtures. The seal fixes the image bytes, transforms,
independent oracle, automatic public runner, thresholds, failure penalties, and
adjudication before the candidate sees the court.

## Why this court is identifiable

The earlier opened synthetic cohort did not satisfy the PRD premise that the
declared truth be identifiable after sampling. Its stored fixed image and
resampled moving image could have a normalized-correlation optimum displaced
from the analytic continuous-image truth. That cohort remains useful for
development but cannot confirm sub-voxel recovery.

The 36 exact rows in this court use a different construction. Each fixed image
is an independently generated analytic phantom stored as float32 NIfTI on a
2 mm grid. Each moving voxel is generated by a standalone Python trilinear
sampler over those stored fixed voxels at the declared moving-to-fixed truth.
The sampled value then receives one positive affine intensity mapping:

```text
moving = 80 + 1.17 * fixed-trilinear-at-truth
```

This relation matches normalized correlation without importing or executing
candidate code. Before sealing, the generator checked up to 4,096 common
full-support points in each exact row. All 36 rows had truth correlation at
least 0.9999999999999439. Fixed perturbations of plus or minus 0.1 mm
translation and 0.3 degrees target-frame rotation, with plus or minus 0.5%
axis scales for affine rows, reduced correlation by at least
1.6391487525635462e-05. The frozen minimum required reduction is 1e-08.

The 12 nonlinear-contrast rows use a signed-square-root intensity mapping.
They remain a descriptive approximation distribution and cannot contribute to
an exact-recovery admission claim.

## Frozen cases and gates

The court has six subjects, four cohorts, and rigid plus affine models: 48 rows
in total and six rows for every cohort/model combination.

| Cohort | Relation | Frozen gate per model |
| --- | --- | --- |
| exact-core | interpolant exact | 6/6 success and every landmark RMS at or below 0.1 mm |
| capture-range | interpolant exact, larger pose | 6/6 success and every landmark RMS at or below 0.25 mm |
| partial-slab | interpolant exact, reduced support | 6/6 success and every landmark RMS at or below 0.25 mm |
| nonlinear-contrast | approximation distribution | descriptive only |

Every sealed row must appear exactly once. A failed row receives a 100 mm
adjudicated error. It must retain a typed failure and detail, work and timing
evidence, and a checkpoint whenever at least one linearization executed.

The runner exposes only the public automatic path: `Flashalign.rigid` or
`Flashalign.affine`, followed by `plan.run(plan.newWorkspace())`, using the
`WithinModality` preset and `CoherentHeaderWorldIdentityThenCapture` policy.
On success it builds `FlashalignOutput` from the original moving image and
materializes one linearly interpolated output on the fixed grid. The output
stage includes plan construction, resampling, and consumption of the result.
There is no supplied transform or development-mode option. Each table row
binds the expected moving and fixed SHA-256 values, which are checked before
the candidate executes.

## Seal and reproduction

The authoritative manifest is
`benchmarks/flashalign/manifests/linear-automatic-confirmation-v1.json`. It
binds the uncommitted candidate snapshot, providers, fixture tree, descriptor,
case table, runner, tests, and summarizer. Its source-tree hash contract uses
repository-relative paths and length-prefixed path and file bytes, so repository
HEAD alone is not treated as the candidate snapshot.

The following pre-execution checks do not run Flashalign on the sealed images:

```bash
python3 benchmarks/flashalign/fixtures/generate_linear_automatic_confirmation.py self-test
python3 benchmarks/flashalign/summarize_linear_automatic_confirmation.py --self-test
sbt -J-Xmx4G -Dsbt.supershell=false 'flashalignBenchmarkJVM/testOnly reframe4s.benchmark.flashalign.LinearAutomaticConfirmationCourtSuite'
```

Regenerating the images is an audit operation: the result must reproduce the
sealed descriptor, table, and image-tree hashes before any candidate run. The
current descriptor binds 48 cases, 54 unique NIfTI files, and 7,291,717 image
bytes.

The first candidate invocation on 2026-09-13 stopped during validation of the
first row and wrote no result rows. The benchmark-only output checksum had
summed non-finite image voxels and exposed a non-finite metric, which the runner
correctly rejected. The preserved attempt record is
`benchmarks/flashalign/raw/linear-automatic-confirmation-2026-09-13-attempt-1.json`.
The correction counts non-finite output voxels explicitly and sums finite
values only. Flashalign source, fixtures, transforms, thresholds, failure
penalty, configuration, and adjudication were unchanged. The runner and seal
were rebound with that history before retrying.

FA-L28 may execute the court only after FA-L27 qualifies exceptional failure
evidence. It must use the exact candidate and provider hashes in the manifest,
preserve all 48 rows, and apply the frozen summarizer without tuning. Complete
cost evidence must include preparation, capture, every refinement attempt,
final audit, and final image sampling when output is produced. Transform-only
timing is not complete output cost.

This court is analytic-synthetic evidence. A passing result would qualify this
specific automatic linear candidate against the frozen conditions; it would
not establish acquired-MRI, anatomical, clinical, publication, or cross-method
superiority claims.
